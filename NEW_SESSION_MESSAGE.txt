## ПОЛНЫЙ ПОТОК «Обсудить на форуме» (финальная логика)

1. Пользователь на любой из 5 страниц кликает «💬 Обсудить на форуме»
   под публикацией.
2. Если гость — открывается AuthModal; после входа нужно кликнуть ещё раз.
3. Если залогинен — браузер делает POST /api/discuss/<kind>/<cuid> с
   токеном.
4. Сервер:
   • Если у публикации уже есть topicId — мгновенно отвечает
     {redirect: "/forum/topic/<id>"} без создания дубликата.
   • Если topicId === null — формирует title и body по правилам блока
     (для employers — employer+city+workPeriod+experience+personMention;
     для остальных — title+text), добавляет ссылку-источник
     «— из публикации: <origin>/<page>#<anchor>-<id>», прогоняет
     модерацию moderateNewText, создаёт Topic + первое Message,
     привязывает topicId к публикации, отвечает
     {redirect: "/forum/topic/<newId>"}.
5. Клиент делает window.location.href = redirect — пользователь попадает
   прямо в тему, где может писать комментарии.
6. При следующем клике под той же публикацией — сервер видит
   topicId !== null и просто редиректит в существующую тему БЕЗ
   создания дубликата.

## ЗАПУСК DEV-СЕРВЕРА (ВАЖНО)

  bash /home/z/my-project/scripts/start-dev.sh

Внутри — setsid + nohup + </dev/null — это критично. Обычный
"nohup bun run dev > log 2>&1 & disown" НЕ работает: package.json
dev-скрипт содержит "| tee dev.log" — пайп убивается при выходе
родительского bash, и сервер падает через ~3 секунды после запуска.
start-dev.sh решает это через setsid + прямой вызов bunx next dev
(минуя package.json dev-скрипт).
